# FlareStar Quant (Gate CrossEx 本地交易终端) — v0.4.1 增量 PRD

> 版本：v0.4.1（基于 v0.4.0，HEAD `a5b3ab6`） · 类型：增量 PRD，仅描述变更部分
> 硬约束：**止损语义保持不变**；所有改动先建 git 分支/tag 备份，本地测试 + 用户验收后才推 Git（本次不涉及推送）；**移动端（手机浏览器）为主要使用场景之一**。

## 1. 产品目标

v0.4.1 是一次"稳定化 + 移动端可用性"版本：修复移动端策略执行卡死、跨所现货-合约对冲平仓后残留单边盈余/负债、资金费率套利一键平仓不干净三类核心交易可靠性问题；通过后端缓存与按时间戳对齐报价，显著提升机会页/资金费率页/策略页加载速度并保证价差展示的是同一时刻真实存在的报价；同时精简顶部导航、合并持仓/挂单列表、上线带排行标签与分页的价差质量榜，让手机端操作路径更短、图标完整可点。交付时改动可回滚（分支/tag），止损行为零变更。

## 2. 用户故事与验收标准

### US-1 移动端策略执行（修复 #1）

> As a 手机端交易者, I want 在手机浏览器填完策略数量和开单价后能正常点"启动策略", so that 我不在电脑前也能抓住机会开仓。

- **AC-1**：iOS Safari / Android Chrome 上，进入任一策略页（paired-position / price-difference / carry 等），填完数量与开单价后点击执行按钮，策略必须实际提交并进入 RUNNING（或弹明确的失败原因）。
- **AC-2**：定位并记录卡死根因（候选：移动端键盘遮挡/滚动导致的点击目标偏移、触摸事件未触发 `onClick`、确认弹窗在视口外、表单校验静默失败），修复后在 PR/日志中说明根因。
- **AC-3**：按钮点击后有 loading/禁用反馈，禁止"点了没反应"的静默状态；重复点击不产生重复下单。

### US-2 页面加载与缓存性能（#2）

> As a 频繁切换页面的用户, I want 机会页、资金费率页、策略页在 1-2 秒内完成首屏数据展示, so that 我能快速判断是否要出手。

- **AC-1**：三个页面首次加载在本地后端上 P95 ≤ 2s 展示出已有数据（不空等全量重算）。
- **AC-2**：后端对机会榜/资金费率/价差质量等重计算结果增加带 TTL 的服务端缓存（复用并扩展现有 `opportunity-board-cache`、`spread-quality` 5 分钟重算机制），同一数据二次请求不重复计算。
- **AC-3**：页面间往返切换时前端优先展示缓存数据并在后台静默刷新，不出现整页白屏/骨架卡顿。

### US-3 跨所现货-合约对冲平仓完整性（#3，重点）

> As a 做跨所对冲（如 Kraken 现货空 + Hyperliquid 合约多、担保资产不同）的用户, I want 平仓后两边资产同时归零、不残留一边盈余一边负债, so that 我的资产页没有永远平不掉的零点几数量代币。

- **AC-1**：平仓流程以**两边交易所的实时余额/持仓**为对账基准（而非本地账本），分别计算每条腿的实际可平数量。
- **AC-2**：对担保资产不同的跨所对冲（不同担保货币），平仓时按担保货币分别处理现货腿（卖出/买入现货）与合约腿（reduce-only），并考虑最小下单量、手续费与价格滑点导致的碎量。
- **AC-3**：平仓完成后做一轮对账校验：若任一腿残留数量 > 该市场最小下单单位，系统必须给出明确提示（复用/扩展现有 `spot-debt-dialog` 模式），说明残量、原因与建议处理方式（如手动补平或调仓），而不是静默留下负债。
- **AC-4**：资产页不显示"已平仓但余额不对称"的僵尸分组；现有分组在平仓后正确收敛。

### US-4 精简顶部导航（#4）

> As a 小屏幕用户, I want 顶部导航更简洁, so that 屏幕空间留给行情和操作。

- **AC-1**：导航视觉层级收敛（建议：一级入口 ≤ 6 个，策略子类型、机会榜单收进下拉/分组菜单），但**全部现有功能与路由均可达**（`frontend-routes.ts` 中所有路由有入口）。
- **AC-2**：桌面端与移动端各有适配布局；移动端导航无横向溢出、无图标被裁切。
- **AC-3**：现有关键路径（开策略、看持仓、一键平仓）点击层级不增加。

### US-5 资金费率套利一键平仓（#5）

> As a 资金费率套利用户, I want 一键平仓把开仓时建立的两条腿全部平干净, so that 不会残留富余负债卡住策略。

- **AC-1**：一键平仓对每条腿独立校验实际持仓/余额并按实际数量下 reduce-only 单（与 v0.4.0 已做的"平仓数量以交易所为准"修复同源、覆盖到 carry/资金费率套利路径）。
- **AC-2**：任一腿失败时不阻塞另一腿平仓，失败腿进入明确的待处理状态并提示；重试以交易所实时余额为准。
- **AC-3**：一键平仓完成后策略状态正确收敛（不残留 RUNNING/PAUSED 卡死状态）。

### US-6 持仓/挂单列表合并（#6）

> As a 跨所交易者, I want 持仓是一个统一列表、挂单是一个统一列表（不再分"合约挂单/现货挂单"两个页签）, so that 我一眼看到全部敞口。

- **AC-1**：持仓页签合并为单一列表，现货与合约持仓同表展示（含市场类型标识），支持按交易所/资产筛选与排序。
- **AC-2**：挂单同理合并为单一列表，现货与合约订单同表展示，支持筛选。
- **AC-3**：现有操作（撤单、平仓、只减仓等）在新列表上全部可用；资产分组持仓视图不受破坏。

### US-7 价差时间对齐与获取时间展示（#7）

> As a 依赖价差决策的用户, I want 看到的价差是同一时刻两边真实报价的差, so that 我不会按一个从未存在过的价差下单。

- **AC-1**：价差计算只使用两边报价的获取时间戳之差 ≤ 阈值（建议默认 ≤ 2s，可配置）的配对；超龄/无法配对的报价不参与价差展示，或明确标注为"不可用/过期"。
- **AC-2**：价差行展示两边报价各自的获取时间（或统一的快照时间）；后端在下发数据时携带时间戳字段。
- **AC-3**：复用并强化现有 `market-freshness`（报价新鲜度闸门），确保策略内部用的价差与页面展示的价差来自同一套对齐逻辑（展示与执行一致性）。

### US-8 价差质量榜排行标签与分页（#8）

> As a 找机会的用户, I want 价差质量榜支持按"平均价差/当前价差/价差波动"等维度切换排序并分页浏览, so that 我能完整浏览全部候选组合而不是固定前 11 条。

- **AC-1**：榜单提供排序标签：平均价差（净均值）、当前价差、价差波动（另有半衰期/深度等 v0.4.0 已有维度可保留）；排序切换即时生效且走服务端参数。
- **AC-2**：分页展示全量候选组合（解除当前约 11 条的展示限制），每页条数固定（建议 20/50），支持翻页；沿用现有执行分页控件 `execution-pagination-control`。
- **AC-3**：后端按所选排序键返回对应页数据（排序在服务端完成，避免前端全量拉取）；缓存 TTL 沿用 ≤ 5 分钟。

### US-9 移动端整体 UX（#9）

> As a 手机浏览器用户, I want 操作路径更短、图标完整显示、触摸目标足够大, so that 手机上不误触、不丢功能。

- **AC-1**：修复所有已知图标显示不全/被吞问题（图标容器尺寸、溢出裁切、字体图标降级）。
- **AC-2**：关键操作按钮触摸目标 ≥ 44×44px；弹窗/对话框在移动端全屏或近全屏，可正常滚动与关闭。
- **AC-3**：横向无页面级滚动；表格在窄屏提供列优先级（次要列折叠或横向滚动但带提示）。
- **AC-4**：以 iOS Safari + Android Chrome 实测通过为验收方式（配合任务 #4 的回归测试）。
